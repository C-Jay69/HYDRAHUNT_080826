The core problem

The app looked finished but several screens invented their own data. A dashboard with hardcoded metrics, a vault with fake saved versions, a career map with demo nodes. Any new user would have been looking at someone else's numbers. That is the fastest way to lose trust on day one.

01

What shipped in this pass

  • Dashboard reads real records. Companies tracked, applications sent, average resume score and interview sessions come from the user's own tables. Loading, empty and error states are explicit.
  • No invented fallbacks. Version Vault, Career Map, Mission Log and the dashboard no longer substitute demo data when an API call fails. They say what failed and offer Retry.
  • Mission Log actually shows activity. The screen was reading the wrong response key, so real events never appeared. It now reads the API's logs array.
  • Application Kit produces all five outputs. Summary, cover letter, outreach email, LinkedIn message and talking points generate in one pass.
  • ATS scores agree between the list and the editor. The resume list now uses the same shared heuristic as the detail view, so no more "No ATS score" on a resume that has one.
  • A-List notes are saved. The add-company dialog was dropping the notes field; it now persists and surfaces failures instead of closing silently.
  • Rewind restores honestly. Create and restore actions report errors rather than pretending a snapshot saved.
  • Interview streaming cancel bug fixed. The stream reader is now reachable from the cancel handler.

03

The build gate

Type safety restored

typescript.ignoreBuildErrors is gone. The 53 errors it hid are fixed, and bun run typecheck now exists as a script.

CI added

A GitHub Actions workflow runs typecheck on every push and pull request, then a production build. Placeholder database credentials let the build import route modules without a live database.

AI calls are bounded

Timeouts, bounded retries and an optional fallback model now wrap every completion. Slow calls log a warning; failures log the model and attempt number.

Privacy and control

A standalone privacy page discloses storage, processors and retention. Settings now includes a typed- confirmation account deletion that cascades through every record and clears the session.

The product does not need more features. It needs the first ten minutes to feel honest, specific and fast.
04

What I would do next

1. Pick one wedge

"Job search workspace" is a category, not a promise. The sharpest wedge here is the five-piece kit: one resume plus one job description, turned into a complete outreach package in a single pass. Lead with that in every channel and put the other tools behind it.

2. Make activation measurable

Define activation as "first application kit generated." Track signup → resume → kit → copy. Until that funnel is instrumented, no marketing spend can be judged.

3. Sell the outcome, not the armoury

People do not buy "AI payload forges." They buy fewer wasted applications. Rewrite pricing and landing copy around time saved and interviews booked. Keep the tool names as navigation, not as the pitch.

4. Build in public

Short screen recordings of one real job turning into a kit will outperform feature lists. Post them where job seekers already are, then let the product do the demo.

5. Earn the privacy story

Career data is sensitive. Say plainly which provider sees resume text, what is retained and how to delete it. Trust is a conversion lever in this category, not a legal checkbox.

6. Keep the free door closed for now

A public ATS checker is a strong acquisition asset, but it is a second product to build and support. Defer it until activation and retention are understood. Spend the first cycle on the paid core.

05

First 90 days, in order

  • Weeks 1–2: instrument the activation funnel and watch ten real users go through signup to first kit. Fix the first place they stall.
  • Weeks 3–4: rewrite the landing page around the kit outcome. Publish three proof-of-work walkthroughs.
  • Weeks 5–8: founder-led outreach to career switchers and laid-off tech workers. Offer a hands-on onboarding call in exchange for feedback.
  • Weeks 9–12: price test Stride against Apex with real usage data. Only then consider a free public checker.
06

Still open

  • Public ATS checker deferred by decision. Revisit after activation is measured.
  • Sample onboarding data not seeded. Empty states now name the next action, but a one-click sample resume would shorten time-to-first-kit.
  • ATS meaning clarified in the UI: Resume Studio estimates content completeness; Fit Check scores against a specific role. The two are not merged.
  • Per-module URLs still unavailable in the SPA. The Field Guide now has a shareable redirect at /field-guide; deeper linking is future work.
